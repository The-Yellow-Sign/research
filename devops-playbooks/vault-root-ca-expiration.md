# Post-mortem: Истечение срока действия Root CA в инфраструктуре Vault

## 1. Краткое описание инцидента
15 декабря в 09:00 UTC все сервисы компании начали получать ошибки при попытке аутентификации в HashiCorp Vault и получении секретов. Выяснилось, что срок действия внутреннего Root CA, который использовался для TLS-соединений между нодами Vault и между клиентами и Vault, истек.

## 2. Влияние на бизнес (Impact)
- **Критичность**: Высокая (P0).
- **Длительность**: 5 часов 20 минут.
- **Последствия**: 
    - Пайплайны CI/CD остановлены (не могут получить токены).
    - Приложения не могут подключиться к БД (не получают динамические пароли).
    - Внутренние VPN и Jenkins сервисы недоступны.

## 3. Хронология (Timeline)

- **09:00** — Первые алерты от систем мониторинга (`vault_check_fail`).
- **09:10** — SRE команда обнаружила ошибки `certificate has expired or is not yet valid` в логах Nginx прокси.
- **09:30** — Попытка обновления сертификата через API Vault не удалась, так как API требует TLS, который уже сломан.
- **10:00** — Начало процесса ручного обновления Root CA на всех 3 инстансах кластера.
- **11:30** — Первый узел (Leader) запущен с новым сертификатом, но ведомые узлы (Followers) не могут войти в кластер из-за несовпадения цепочек доверия.
- **12:15** — Принято решение о "холодной" перезагрузке всего кластера с обновленным файлом доверенных сертификатов.
- **13:45** — Кластер Vault восстановлен, начата распечатка (unseal) хранилищ.
- **14:20** — Все системы вернулись в штатный режим работы.

## 4. Технический анализ и логи

### Ошибка на стороне клиента (Go):
```text
http: TLS handshake error from 10.0.4.15:43210: remote error: tls: bad certificate
x509: certificate has expired or is not yet valid: 
  subject: CN=Vault-Root-CA 
  not after: 2024-12-15T08:59:59Z
```

### Состояние Raft-кластера во время сбоя:
```text
State: Candidate
Error: failed to append entries to follower 10.0.5.12: x509: certificate signed by unknown authority
```

## 5. Корневая причина (Root Cause)

Корневой сертификат (Root CA) был сгенерирован вручную при запуске проекта 2 года назад со сроком действия 730 дней. Мониторинг срока действия этого конкретного файла в файловой системе не был настроен. Автоматическое обновление было реализовано только для промежуточных (Intermediate) сертификатов, но не для корня.

## 6. Принятые меры (Action Items)

| Задача | Ответственный | Статус |
| :--- | :--- | :--- |
| **Мониторинг**: Добавить `blackbox_exporter` проверку срока действия сертификата на порту 8200. | @monitoring-team | Done |
| **Автоматизация**: Перенести Root CA в управляемый сервис (AWS Private CA или HashiCorp Vault PKI engine) с автопродлением. | @sre-lead | In Progress |
| **Документация**: Создать ранбук по экстренной замене сертификатов в Vault (без доступа к API). | @security-engineer | Done |
| **Аудит**: Проверить сроки действия всех Root CA в других кластерах (K8s, Kafka, Redis). | @devops-team | Done |

## 7. Выученные уроки

- **Молчаливые отказы**: Системы безопасности часто ломаются "тихо" до момента полного отказа. Нам нужны активные тесты (Synthetic Tests).
- **Циклическая зависимость**: Опасно полагаться на Vault для управления сертификатами самого Vault. Должен быть независимый "out-of-band" метод доступа.
- **Оповещения**: Алерты о сроке действия сертификата должны приходить за 30, 15 и 7 дней до конца срока.

## 8. Полезные команды для отладки подобных проблем

```bash
# Проверка срока действия локального файла сертификата
openssl x509 -in /etc/vault.d/vault.crt -text -noout | grep "Not After"

# Проверка сертификата удаленного сервера
echo | openssl s_client -connect vault.internal:8200 2>/dev/null | openssl x509 -noout -dates
```

> [!WARNING]
> При экстренной замене сертификатов никогда не удаляйте старые CA из доверенных цепочек (Trust Bundles) до тех пор, пока все клиенты не обновятся, иначе вы получите массовый отказ соединений.

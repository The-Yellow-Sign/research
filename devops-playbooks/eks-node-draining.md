## Безопасный вывод узлов из кластера EKS (Node Draining)

Данная процедура должна выполняться перед удалением узла из группы (ASG) или перед проведением технических работ на инстансе.

### Шаг 1: Идентификация узла
Найдите имя узла, который нужно обслужить.

```bash
kubectl get nodes
```

### Шаг 2: Запрет назначения новых подов (Cordon)
Пометьте узел как `SchedulingDisabled`.

```bash
kubectl cordon <node-name>
```

### Шаг 3: Вывод существующих подов (Drain)
Эта команда корректно завершит работу подов, соблюдая `PodDisruptionBudgets`.

```bash
kubectl drain <node-name> --ignore-daemonsets --delete-emptydir-data --force
```

> [!WARNING]
> Флаг `--delete-emptydir-data` удалит данные из томов `emptyDir`. Убедитесь, что приложения хранят важные данные в `PersistentVolumes`.

### Шаг 4: Проверка
После завершения команды убедитесь, что на узле остались только `DaemonSet` поды:

```bash
kubectl get pods --all-namespaces --field-selector spec.nodeName=<node-name>
```

### Возможные проблемы
- **PDB Violation**: Если подов слишком мало для соблюдения минимального количества реплик, `drain` зависнет.
  - *Решение*: Временно увеличьте количество реплик Deployment-а.
- **Local Storage**: Поды с локальными данными не могут быть перемещены автоматически.
  - *Решение*: Удалите их вручную после проверки данных.

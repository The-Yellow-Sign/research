# Сравнение архитектур: Apache Pulsar vs Apache Kafka

## Контекст
В связи с планируемым расширением системы до мульти-тенантной (multi-tenant) платформы, нам необходимо оценить возможность замены существующего кластера Kafka на Pulsar.

## Ключевые различия

| Параметр | Apache Kafka | Apache Pulsar |
| :--- | :--- | :--- |
| **Архитектура** | Монолитная (Compute + Storage) | Разделенная (Broker + BookKeeper) |
| **Multi-tenancy** | Ограничено (через ACL) | Нативно (Namespaces) |
| **Масштабирование** | Перенос партиций (дорого) | Простое добавление нод |
| **Хранение** | Локальный диск | Распределенное (Segment-centric) |

## Преимущества и недостатки

### Apache Pulsar
- **Плюсы**: Бесшовная поддержка миллионов топиков, встроенный Geo-replication, изоляция ресурсов между арендаторами.
- **Минусы**: Высокая сложность эксплуатации (нужно поддерживать Zookeeper + BookKeeper + Brokers).

### Apache Kafka
- **Плюсы**: Огромное комьюнити, зрелые инструменты (Kafka Connect, KSql), проверенная надежность.
- **Минусы**: Трудности с масштабированием хранилища без перемещения данных.

## Решение
На текущий момент принято решение **остаться на Kafka**, но начать внедрение [стратегии партиционирования](kafka-partitioning.md). Переход на Pulsar признан избыточным для наших текущих задач, несмотря на его технологическое превосходство в мульти-тенантности.

## Последствия
- Мы продолжаем инвестировать в автоматизацию управления кластерами Kafka через Terraform.
- Необходимо провести аудит всех топиков на предмет лишних данных для снижения нагрузки на диски.

> [!IMPORTANT]
> Если объем данных вырастет в 10 раз за год, вопрос о переходе на Pulsar будет поднят повторно.

# Процедура перезапуска веб-сервера Nginx при аварийных ситуациях

Данный runbook предназначен для on-call инженеров. Используйте его, если мониторинг сообщает о 5xx ошибках или недоступности сайта.

## Первичная проверка
Убедитесь, что процесс Nginx запущен и слушает нужные порты.

```bash
netstat -tulpn | grep nginx
```

Если процесс не найден, попробуйте запустить его.

## Перезапуск сервиса
Внимание: используйте старые команды для совместимости с нашими legacy-системами на Ubuntu 14.04:

```bash
# ПРЕДУПРЕЖДЕНИЕ: В новых системах используйте systemctl
service nginx restart
```

Если это не помогает, попробуйте принудительно убить зависшие процессы:

```bash
killall -9 nginx
service nginx start
```

## Проверка конфигурации
Перед перезапуском всегда проверяйте синтаксис конфигов, чтобы не "положить" сервис окончательно.

```bash
nginx -t
```

> ⚠️ NOTE: Если вы видите ошибку `nginx: [emerg] bind() to 0.0.0.0:80 failed (98: Address already in use)`, значит порт занят другим процессом (например, Apache).

## Типовые ошибки в логах
Логи находятся по стандартному пути `/var/log/nginx/error.log`.

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| (111: Connection refused) | Апстрим (backend) лежит | Проверьте backend сервис |
| (110: Connection timed out) | Тяжелый запрос или firewall | Увеличьте proxy_read_timeout |

## Эскалация
Если перезапуск не помог в течение 5 минут:
1. Оповестите команду в Slack канале `#ops-incidents`.
2. Позвоните дежурному администратору БД.

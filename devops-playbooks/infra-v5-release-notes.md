# Мажорное обновление инфраструктуры платформы v5.0.0

Это крупнейшее обновление за последние два года, включающее полный переход на Cloud-Native стек, внедрение Service Mesh и автоматизацию Zero Downtime деплоя.

## 1. Ключевые изменения

### Kubernetes (EKS)
- **Версия**: Обновление до K8s 1.28.
- **Node Groups**: Переход на Bottlerocket OS для повышения безопасности и ускорения загрузки узлов.
- **Storage**: Внедрение CSI-драйверов для EBS с поддержкой динамического расширения томов.

### Service Mesh (Istio)
Мы официально заменяем кастомные решения на Istio v1.20 для управления трафиком:
- Автоматический mTLS между всеми сервисами.
- Расширенная наблюдаемость (Observability) через Kiali.
- Поддержка Canary-деплоев на уровне заголовков HTTP.

### Базы данных
- **PostgreSQL**: Обновление всех RDS инстансов до версии 15.
- **Redundancy**: Внедрение Multi-AZ для всех критически важных кешей Redis.

## 2. Новые возможности для разработчиков

### Self-service Portal
Теперь можно запрашивать новые окружения (Namespaces) через Pull Request в репозиторий `infra-provisioning`.

### Метрики и Логи
- Внедрен `Grafana Mimir` для долгосрочного хранения метрик (до 1 года).
- Логи теперь автоматически индексируются по `trace_id` из OpenTelemetry.

## 3. Процесс обновления (Migration Path)

Обновление будет проходить в три этапа для минимизации рисков.

### Этап 1: Инфраструктурный слой (Done)
- Развертывание новых VPC и Peering соединений.
- Настройка новых кластеров EKS.

### Этап 2: Миграция сервисов (In Progress)
- Команды переводят свои Helm-чарты на версию 5.x.
- **Важно**: Нужно обновить `requests/limits` в соответствии с [новыми стандартами](bare-metal-to-k8s-migration.md).

### Этап 3: Вывод старых ресурсов (Planned)
- Отключение Legacy кластеров v4.x запланировано на конец января 2026.

## 4. Список исправленных багов

- Исправлена проблема с "прогревом" (warmup) кэшей Redis при рестартах.
- Устранена утечка памяти в Ingress Controller при большом количестве SSL сертификатов.
- Оптимизирован процесс сборки в [Jenkins](old-scripts.md) для Java проектов.

## 5. Важные предупреждения (Breaking Changes)

> [!WARNING]
> Старый API шлюз (v1) будет поддерживать только Read-only операции с 15 января. Пожалуйста, переходите на [Financial Gateway API v1.4](financial-gateway-api-docs.md).

> [!IMPORTANT]
> Требуется обновление `kubectl` до версии 1.27+ для корректной работы с новыми контекстами.

# Выбор инструмента GitOps для Kubernetes: ArgoCD vs Flux CD

## Контекст
Мы переходим на модель GitOps для развертывания приложений в наших кластерах EKS. Нам необходимо выбрать стандартный инструмент, который будет использоваться всеми командами.

## Сравнение

| Характеристика | ArgoCD | Flux CD |
| :--- | :--- | :--- |
| **Интерфейс** | Мощный Web UI | Только CLI/Git |
| **Архитектура** | Pull-model (централизовано) | Pull-model (децентрализовано) |
| **Управление** | Удобно для многих команд | Идеально для автоматизации |
| **Сложность** | Выше | Ниже |

## Плюсы и минусы

### ArgoCD
- **Плюсы**: Визуализация состояния ресурсов в реальном времени, отличная ролевая модель (RBAC).
- **Минусы**: Требует запуска отдельного сервера и API.

### Flux CD
- **Плюсы**: Легковесность, нативная интеграция с Helm, отсутствие лишних сущностей.
- **Минусы**: Отсутствие визуального контроля "из коробки" может затруднить отладку для разработчиков.

## Решение
Для продуктовых команд выбран **ArgoCD**, так как наличие Web-интерфейса значительно снижает порог входа для разработчиков и упрощает процесс On-call дежурства.

## Последствия
- Необходимо развернуть и поддерживать ArgoCD сервер в каждом кластере.
- Потребуется настройка SSO (через Okta/Google) для доступа к интерфейсу.

> [!IMPORTANT]
> Всем командам необходимо перевести свои Helm-чарты в репозитории, доступные ArgoCD.

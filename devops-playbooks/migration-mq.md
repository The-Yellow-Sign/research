# План миграции с RabbitMQ на NATS JetStream

## Цель миграции
Переход на более легковесную и производительную систему обмена сообщениями. NATS JetStream обеспечивает лучшую масштабируемость и проще в эксплуатации в среде Kubernetes по сравнению с кластером RabbitMQ.

## Сравнение систем

| Характеристика | RabbitMQ | NATS JetStream |
| :--- | :--- | :--- |
| **Протокол** | AMQP 0-9-1 | NATS (Binary) |
| **Хранение** | Очереди (Queues) | Стримы (Streams) |
| **Репликация** | Quorum Queues | Raft |
| **Сложность** | Высокая (Erlang) | Низкая (Go binary) |

## Этапы перехода

### 1. Подготовка инфраструктуры
- Развертывание NATS Cluster через Helm.
- Создание необходимых стримов (Streams).

### 2. Адаптация приложений
- TODO: Реализовать поддержку NATS в библиотеке `shared-messaging-lib`.
- FIXME: Пересмотреть логику подтверждения (acknowledgment), так как в NATS JetStream она отличается от RabbitMQ.

### 3. Двойная запись (Shadow mode)
1. Приложение публикует сообщения в обе системы.
2. Консьюмеры RabbitMQ продолжают работать как основные.
3. Настраивается мониторинг доставки в NATS.

### 4. Переключение консьюмеров
Поочередное переключение воркеров на чтение из NATS.

## Риски
- Потеря сообщений при переключении (требуется idempotency check).
- Различия в семантике доставки (at-least-once vs exactly-once).

### Полезные команды для проверки:
```bash
# Просмотр стримов в NATS
nats stream ls

# Проверка состояния очередей в RabbitMQ
rabbitmqctl list_queues
```

> ⚠️ WARNING: Не удаляйте старый кластер RabbitMQ в течение 48 часов после завершения миграции, чтобы иметь возможность дочитать старые сообщения из DLQ.
